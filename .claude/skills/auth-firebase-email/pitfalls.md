# Firebase Auth (Email) — Pitfalls Catalog

16 entries from FlutterFire issues + Firebase docs + KVKK/GDPR + Apple/Play policies.

| # | Symptom | Cause | Fix | Source |
|---|---|---|---|---|
| 1 | `wrong-password` and `user-not-found` no longer thrown; only `invalid-credential` returned | **Email enumeration protection** (default-on for projects after 2023-09-15) merges these to prevent leaking which emails are registered | Map both `invalid-credential` and `invalid-login-credentials` to `InvalidCredentialsException` → "E-posta veya şifre hatalı" generic UI | [Cloud Identity Platform docs](https://cloud.google.com/identity-platform/docs/admin/email-enumeration-protection) |
| 2 | `linkWithCredential` for anonymous → email throws `operation-not-allowed` or `email-already-in-use` even when the email is brand new | Email enumeration protection breaks the anonymous-upgrade path because Firebase can't safely check email existence | Either disable email enumeration protection in Cloud Console (lowers security), OR migrate user to a fresh account and copy data server-side | [GH #11703](https://github.com/firebase/flutterfire/issues/11703) |
| 3 | `user.email` still shows old email after `verifyBeforeUpdateEmail` | New email isn't applied until user clicks verification link sent to NEW address; current session continues with old email | After link click, call `user.reload()` then re-read `user.email`; tell user "Yeni adresinize gönderilen linke tıklayın" | [FlutterFire docs](https://firebase.flutter.dev/docs/auth/manage-users/) |
| 4 | `emailVerified` stays `true` after changing email | `verifyBeforeUpdateEmail` requires the new email to be verified, but the current `User.emailVerified` doesn't auto-flip | Force `await user.reload()` after the link is clicked. Don't gate by emailVerified before reload | [Kazulog](https://kazulog.fun/en/dev-en/firebase-email-verified-not-working-error/) |
| 5 | `updatePassword` / `delete()` / `verifyBeforeUpdateEmail` throws `requires-recent-login` | Sensitive operations require sign-in within ~5 minutes | Catch as `ReauthRequiredException`; prompt user for password + biometric, call `reauthenticateWithCredential`, retry | [Firebase docs](https://firebase.google.com/docs/auth/flutter/manage-users) |
| 6 | Email verification deep-link doesn't open the app on iOS | `ActionCodeSettings.dynamicLinkDomain` is no-op (Dynamic Links deprecated 2024) and Universal Links not configured | Configure Firebase Hosting custom domain + AASA + Associated Domains capability — see `deeplinks-go-router` skill | [GH #12167](https://github.com/firebase/flutterfire/issues/12167) |
| 7 | `sendEmailVerification` succeeds but no email arrives | Often Firebase quota / spam filter; or sender domain not verified | Add Firebase to SPF / configure custom email domain in Firebase Console → Authentication → Templates → SMTP settings | [blog.flutter.wtf](https://blog.flutter.wtf/firebase-authentication-issues/) |
| 8 | `email-already-in-use` race during account linking | Two concurrent sign-up attempts; or user already created via Google then tries email/password with same address | Catch `account-exists-with-different-credential`, prompt user to sign in with original provider then link new credential via `linkWithCredential` | [GH #11845](https://github.com/firebase/flutterfire/issues/11845) |
| 9 | Custom claims set on backend not reflected on client | `idTokenChanges` doesn't auto-fire when claims change server-side | After server claim change, call `user.getIdToken(true)` to force refresh | [Firebase admin claims](https://firebase.google.com/docs/auth/admin/custom-claims) |
| 10 | Action code (password reset / email verification link) returns `invalid-action-code` | Code already used or expired (default: 1 hour for email verification, 1 hour for password reset) | Detect, show "Link süresi doldu" UI, offer "send new link" button | [FlutterFire errors](https://firebase.flutter.dev/docs/auth/error-handling/) |
| 11 | Crash on iOS calling `sendEmailVerification` then quickly `signOut` | Pre-6.3.0 Firebase iOS SDK race | Upgrade to `firebase_auth >= 6.3.0`; debounce back-to-back calls | [pub changelog](https://pub.dev/packages/firebase_auth/changelog) |
| 12 | `validatePassword(pwd)` not available client-side | Web SDK has it; Flutter SDK does not | Mirror your project's password policy in client-side regex; fall back on `weak-password` server error | [GH #11816](https://github.com/firebase/flutterfire/issues/11816) |
| 13 | After `delete()` user can still sign in for ~1h on a different device | ID tokens valid for 1 hour and aren't revoked on delete | Listen to `userChanges` on all devices, call `getIdToken(true)`; if returns user-not-found / token revoked, force sign-out. Set `revocation: true` on critical Cloud Function `verifyIdToken(token, true)` checks | community |
| 14 | Account orphan data in Firestore/Storage after `user.delete()` | `user.delete()` only removes the auth record, not data | Install **Delete User Data extension** OR write `onUserDeleted` Cloud Function (see [snippets/onUserDelete.ts](snippets/onUserDelete.ts)) — KVKK Art. 7 + GDPR Art. 17 require deletion within 30 days | [Firebase ext](https://firebase.google.com/docs/extensions/official/delete-user-data) |
| 15 | Flutter `signInWithEmailAndPassword` throws `unknown` instead of mapped code on web | firebase_auth_web bug under enumeration protection | Use `firebase_auth >= 6.3.0`; map `unknown` to invalid-credential as defensive fallback | [GH #12309](https://github.com/firebase/flutterfire/issues/12309) |
| 16 | After `signOut`, app still shows cached user data | In-memory state held by Riverpod providers/notifiers | After `signOut`, call `ref.invalidate(...)` on all auth-derived providers; clear `flutter_secure_storage`; reset analytics user-id | best practice |
