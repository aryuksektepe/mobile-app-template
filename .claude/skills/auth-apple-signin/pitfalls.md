# Sign in with Apple — Pitfalls Catalog

22 entries from `sign_in_with_apple` GitHub, FlutterFire issues, Apple Developer Forum,
and production Bug 12 (Supabase + relay-email UX run — #19–#22).

| # | Symptom | Cause | Fix | Source |
|---|---|---|---|---|
| 1 | `[firebase_auth/invalid-credential] Invalid OAuth response from apple.com` | Hashed nonce sent to Apple but **forgot to send raw nonce** to Firebase, or vice versa | Send **SHA256-hashed** nonce to `getAppleIDCredential(nonce: ...)` AND **raw** nonce to `OAuthProvider.credential(rawNonce: ...)`. Both from same source | [Muhammad Fathy](https://medium.com/@muhammad.fathy/resolving-the-firebase-auth-invalid-credential-invalid-oauth-response-from-apple-com-6bca6b6a8575) |
| 2 | `displayName` always null after first sign-in | Apple only returns name + email on **the very first** sign-in for a given Apple ID + app combo. If you don't save it then, gone forever | Capture `givenName` + `familyName` from credential, write to Firestore + `user.updateDisplayName` immediately. Wrap in try/retry. To re-test: Settings → Apple ID → Sign-In & Security → Apps Using Apple ID → remove your app, then re-sign-in | [GH #10057](https://github.com/firebase/flutterfire/issues/10057) |
| 3 | App Review rejection — "Sign in with Apple required" (Guideline 4.8) | Offering Google/Facebook/X login on iOS without Apple | Add Sign in with Apple to iOS, hide the button on Android via `Platform.isIOS` check | [WorkOS 2025 guide](https://workos.com/blog/apple-app-store-authentication-sign-in-with-apple-2025) |
| 4 | `Invalid OAuth response` on Android only, works on iOS | Android uses the **web flow** via your Service ID + redirect URI; Service ID misconfigured | Verify Apple Service ID has both Domains (without `https://`) AND Return URLs (with full URL); redirectUri in Flutter code must match exactly | [Selvaraj Mani](https://medium.com/@selvarajmani/implementing-apple-id-sign-up-and-login-for-flutter-android-and-java-be-using-rest-based-redirect-9ed594846acf) |
| 5 | "Sign in with Apple is not configured" / fails with no error in iOS | Capability not added in Xcode | Runner → Signing & Capabilities → + Sign in with Apple. Re-run pod install if needed | sign_in_with_apple README |
| 6 | `INVALID_CLIENT` from Apple's token endpoint (server-side) | Wrong client_id (using App ID for web flow, or Service ID for native), or JWT signature wrong, or JWT expiration > 6 months | Native iOS uses **App ID** as client_id; Android/Web uses **Service ID**. JWT exp must be ≤ 6 months from iat. Sign with downloaded `.p8` using ES256 | [Fluffy.es](https://fluffy.es/how-to-solve-invalid_client-error-in-sign-in-with-apple/) |
| 7 | User picked "Hide my email" → emails to `xxx@privaterelay.appleid.com` bounce | Outbound sender domain not registered with Apple's relay service | Apple Developer Portal → Configure Email Sources → register domain + email + add SPF/DKIM. Verify postmaster receives bounce reports | [Apple docs](https://developer.apple.com/help/account/capabilities/configure-private-email-relay-service) |
| 8 | Bounce: user deleted their Hide-My-Email alias | User revoked, or daily 100-msg cap | Show "İletilemedi" UI; require user to re-enter primary email. Don't store relay address as authoritative contact | [SpamResource](https://www.spamresource.com/2020/05/help-all-mail-to-privaterelayappleidcom.html) |
| 9 | `requires-recent-login` when calling `user.delete()` weeks after sign-in | Sensitive op needs <5min auth | Re-trigger Apple sign-in inside delete flow; call `reauthenticateWithCredential` with fresh OAuth credential (full nonce dance) | Marwa Diab Medium |
| 10 | Account deletion succeeds in Firebase but Apple still lists app under "Apps Using Apple ID" | Forgot to call `revokeToken` — Apple **requires** explicit revocation as of June 2022 | Save `authorizationCode` on each sign-in via `storeAppleAuthCode` Cloud Function; on delete, call `revokeTokenWithAuthorizationCode` (or REST `/auth/revoke`) BEFORE `user.delete()`. App Review will reject if missed | [jooyoungho example](https://github.com/jooyoungho/apple-token-revoke-in-firebase) |
| 11 | `revokeToken` fails: "no refresh token stored" | Firebase doesn't store Apple refresh_token automatically; you must pass authorizationCode from a fresh sign-in | Always force user to re-sign-in to get a fresh `authorizationCode` before revocation flow | [GH #11065](https://github.com/firebase/flutterfire/issues/11065) |
| 12 | Refresh token unexpectedly invalid | User changed Apple ID password; token rotates on password change | Detect `invalid_grant` on backend; treat user as signed out; re-prompt sign-in | [Apple forum](https://developer.apple.com/forums/thread/720965) |
| 13 | Web flow opens in modal but user reports "blank screen" | Popup blocked, or redirect URL mismatch | Trigger from a real user gesture; verify exact match (trailing slash matters); whitelist popup in CSP | sign_in_with_apple docs |
| 14 | `account-exists-with-different-credential` when same user signs in via Apple after using email/password | Firebase blocks linking when email is already registered | Catch, sign user in with the existing provider, then `linkWithCredential(appleCredential)` to merge | Firebase docs |
| 15 | iOS user's email returns `null` even on first sign-in | User selected "Hide My Email" + you didn't request `email` scope, OR app reads from `appleCredential.email` (only first sign-in) | Always include `AppleIDAuthorizationScopes.email`. After Firebase sign-in, read `firebaseUser.email` (Firebase persists it) — not `apple.email` | [GH #11658](https://github.com/firebase/flutterfire/issues/11658) |
| 16 | Cloud Function client-secret JWT rejected | `iss` must be Team ID, `sub` must be Service ID (web) or App ID (native), `aud` must be `https://appleid.apple.com`, `kid` header = Key ID | Double-check JWT header (`alg=ES256`, `kid=<KEY_ID>`) and payload | [Apple JWT docs](https://developer.apple.com/documentation/sign_in_with_apple/generate_and_validate_tokens) |
| 17 | After hot restart on iOS, sign in with Apple sheet doesn't appear | Plugin state mismatch | Cold-start the app; not a production issue | community |
| 18 | `SignInWithAppleAuthorizationException(canceled)` but user didn't cancel | On Android, closing the Chrome Custom Tab manually counts as cancel (since 6.x) | Treat as soft cancel; inform user "İşlem iptal edildi" without error UI | [pub changelog](https://pub.dev/packages/sign_in_with_apple/changelog) |
| 19 | Kullanıcı "Hide My Email" seçti → her yerde `xxxxxxxx@privaterelay.appleid.com` görünür, kullanıcı kafası karışıyor ("bu email ne?") | Relay email Apple'ın hakkı — gerçek email'i zorla istemek 4.8 ihlali | Pattern: `auth_email` (relay, AUTH için, UI'da gizli) + `display_name` (kullanıcının manuel girdiği, UI'da gösterilen) + opsiyonel `contact_email` (kullanıcı tercihi). Helper: `isAppleRelayEmail(email) → endsWith('@privaterelay.appleid.com')`; göstermede "Apple ID" fallback | production Bug 12 (Spotify/Notion/Linear pattern) |
| 20 | Apple ilk sign-in'de `givenName`+`familyName` verdi, ama kullanıcı Hide-My-Email kullandığı için `auth_email` relay → uygulamada hâlâ "Apple ID" görünür (display name kaydedilmemiş) | İlk sign-in callback'inde sadece Firebase Auth `updateDisplayName` çağrıldı ama profile tablosuna ayrı yazılmadı; sonraki login'lerde Apple `name=null` döner — kalıcı kayıp | İlk sign-in callback'inde DERHAL `profiles.display_name = '${givenName} ${familyName}'` upsert et (Supabase/Firestore). Race kalmasın diye `await` ile, retry sarmalı. Eğer name yine boş → first-launch MainShell post-frame callback'te `showSetDisplayNameDialog(showAsFirstPrompt: true)` zorunlu prompt + `SharedPreferences` dismiss key | production Bug 12 |
| 21 | (Supabase tarafı) `signInWithIdToken` "Nonces mismatch" hatası | `sign_in_with_apple` Apple'a SHA256-hashed nonce gönderir, Supabase RAW nonce bekler | İki nonce dance Firebase'le aynı: `getAppleIDCredential(nonce: sha256(raw))` + `supabase.auth.signInWithIdToken(idToken, nonce: rawNonce)`. Çağrı: ```dart\nfinal rawNonce = generateNonce();\nfinal hashed = sha256.convert(utf8.encode(rawNonce)).toString();\nfinal cred = await SignInWithApple.getAppleIDCredential(nonce: hashed, scopes: [.email, .fullName]);\nawait Supabase.instance.client.auth.signInWithIdToken(provider: OAuthProvider.apple, idToken: cred.identityToken!, nonce: rawNonce);\n``` | [Supabase Apple docs](https://supabase.com/docs/guides/auth/social-login/auth-apple) |
| 22 | "PIN unuttum" / "Hesabımı sil" akışında relay-email kullanıcısı destek mailinden yanıt alamıyor (relay forwarding fail) | Apple relay'den postmaster bounce'lar; relay daily 100-msg cap aşıldı veya user revoked | App-içi support flow: relay'e güvenme — alternatif iletişim için `contact_email` opsiyonel field ekle, prompt göster: "İletilemiyorsa şuradan: ..." | bkz #7, #8 |
