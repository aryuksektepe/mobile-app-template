# Account Deletion — Pitfalls Catalog

10 entries from Apple App Review reports, Play Store policy advisories, FlutterFire issues, RevenueCat docs, KVKK/GDPR guidance.

| # | Symptom | Cause | Fix | Source |
|---|---|---|---|---|
| 1 | App Review reject 5.1.1(v): "deletion is incomplete" | SIWA users — Apple refresh token never revoked server-side; Apple checks during review | Add step 5 (POST /auth/revoke with the persisted refresh token); requires server-side JWT signing with .p8 | [Apple Guideline 5.1.1(v)](https://developer.apple.com/app-store/review/guidelines/#data-collection-and-storage) |
| 2 | App Review reject — "delete account button hard to find" | Buried more than 2 taps from Account UI, or labeled "Deactivate" / "Close" | Reachable ≤2 taps from main Account screen; label "Delete account" or local equivalent | [Apple Reject reasons](https://developer.apple.com/app-store/review/guidelines/) |
| 3 | Play Store reject — "deletion option is web-only / email-based" | Deletion only via support email or external web form | Must be in-app actionable; email/web as a backup is OK but not primary | [Play Account Deletion policy](https://support.google.com/googleplay/android-developer/answer/13316080) |
| 4 | `FirebaseAuthException: requires-recent-login` mid-flow | Last sign-in >5 min ago when `user.delete()` is called | Reauth gate as step 3, not at step 9; provider-specific reauth (email/pwd / Google / Apple / phone) | [FlutterFire Auth](https://firebase.flutter.dev/docs/auth/usage/#reauthenticate-a-user) |
| 5 | User charged $9.99 the day after deleting account | Subscription is store-managed, NOT app-managed — deleting account doesn't cancel sub | Warn before step 4 with deep link to iOS Settings → Subscriptions / Play Store subs page | [Apple StoreKit docs](https://developer.apple.com/documentation/storekit) |
| 6 | After deletion, the user's old device receives a notification for "their" topic | FCM token left on server; topic targeting still includes the (now-orphaned) token | Step 7: device-side `deleteToken()` AND server-side row delete in `fcm_tokens(userId, deviceId, token)` | [Firebase FCM tokens](https://firebase.google.com/docs/cloud-messaging/manage-tokens) |
| 7 | RC dashboard still shows the deleted user under "active subscribers" | Only `Purchases.logOut()` called — that just unsets the SDK user, doesn't delete | Add step 6: REST `DELETE /v1/subscribers/{user_id}` with secret API key (server-side only) | [RC API reference](https://www.revenuecat.com/reference/delete-customer) |
| 8 | "Account deleted" toast shows but user signs in again next day and account is back | Soft-delete (status='pending_delete') was meant but no hard-purge cron deployed | Deploy purge cron (sample in `snippets/purge_pending_deletions.ts`); the 30-day grace is correct, the missing hard-purge is the bug | KVKK §17 + GDPR §17 |
| 9 | KVKK violation report — user requested deletion 60 days ago but their email is still in BigQuery | Firebase Analytics historical rows in BigQuery export are NOT deleted by `resetAnalyticsData()` | Separate DSAR (Data Subject Access Request) flow against BigQuery; document SLA in privacy policy | [GA4 user deletion](https://support.google.com/analytics/answer/9940393) |
| 10 | Deletion fails silently — UI says success but server row still there | Step 4 error swallowed because UI only checks `FirebaseAuth.delete()` (step 9) outcome | Each step throws on irrecoverable failure with `AccountDeletionError(step, cause)`; UI prompts "retry from step N" | this skill's own pattern |
