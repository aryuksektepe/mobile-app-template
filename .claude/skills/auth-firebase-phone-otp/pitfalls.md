# Phone OTP — Pitfalls Catalog

| # | Symptom | Cause | Fix | Source |
|---|---|---|---|---|
| 1 | iOS simulator: every send fails with `missing-client-identifier` | Silent push verification fails on simulator (no APNs) — reCAPTCHA fallback not enabled | Enable reCAPTCHA fallback OR test on real device. Production iOS uses silent push (APNs token required) | [Firebase Phone iOS](https://firebase.google.com/docs/auth/ios/phone-auth) |
| 2 | Android: every send returns `app-not-authorized` | Play Integrity API not enabled / not configured in Firebase Console | Console → Project Settings → App Check → Play Integrity → enable + add SHA-256s for every flavor | [Firebase Play Integrity migration](https://firebase.google.com/docs/auth/android/play-integrity) |
| 3 | Test phone number returns `invalid-phone-number` | Test numbers only registered in DEV Firebase project — running PROD project | Add the same test numbers to PROD Auth → Phone → Test numbers, or guard test path by flavor | [Firebase test numbers](https://firebase.google.com/docs/auth/web/phone-auth#test-with-fictional-phone-numbers) |
| 4 | SMS auto-retrieval works in debug, fails in release | App hash differs between debug + release signing keys; SMS Retriever expects matching hash | Compute hash for release keystore (`AppSignatureHelper` Java tool) + use both during testing | [SMS Retriever API](https://developers.google.com/identity/sms-retriever/overview) |
| 5 | "Too many requests" after a few dev iterations | Firebase rate-limits unverified phone numbers (~5/15min, ~50/day) | Use test phone numbers in dev; production users not affected | [Firebase rate limits](https://firebase.google.com/docs/auth/limits) |
| 6 | OTP entered but `invalid-verification-code` even with correct digits | `verificationId` lost (e.g. UI rebuild dropped state) | Persist `verificationId` in Riverpod (per snippet); never recompute from screen rebuild | [FlutterFire Phone API](https://firebase.flutter.dev/docs/auth/phone) |
| 7 | User has both phone + email accounts in Firebase — sign-in confused | Phone + email created independently — separate auth records | Use `linkWithCredential` after first sign-in to merge into one account (per `auth-firebase-email`) | [FlutterFire account linking](https://firebase.flutter.dev/docs/auth/usage/#link-an-account) |
| 8 | Pinput auto-fill works but next text input grabs the same SMS code from clipboard | iOS leaks the OTP via UIPasteboard between apps | Use Pinput's `pinAnimationType` + iOS doesn't fully respect, but the visible UX is acceptable; mitigation = clear clipboard after auto-fill (`Clipboard.setData(ClipboardData(text: ''))`) | iOS UIPasteboard behavior |
| 9 | Country code picker shows wrong default for TR users | Hard-coded `defaultCountry: 'US'` | Detect from device locale: `WidgetsBinding.instance.platformDispatcher.locale.countryCode` | country_code_picker docs |
| 10 | `verifyPhoneNumber` never calls any callback on iOS | iOS Capabilities → Background Modes → Push Notifications NOT enabled | Enable Background Modes → Push + Remote notifications; APNs key uploaded to Firebase | [Firebase iOS APNs setup](https://firebase.google.com/docs/cloud-messaging/ios/certs) |
