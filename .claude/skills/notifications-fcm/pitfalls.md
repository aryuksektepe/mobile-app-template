# Notifications (FCM + Local) — Pitfalls Catalog

22 entries from FlutterFire docs, GitHub issues, Pushy/Android dev research,
two real production runs (push-navigation campaign — #15–#16; a
production Bug 11 hybrid local+FCM dedup — #17–#22).

| # | Symptom | Cause | Fix | Source |
|---|---|---|---|---|
| 1 | Android notification shows white square instead of logo | Adaptive icon with non-transparent background; Android paints a single-color silhouette | Generate transparent monochrome PNG via Android Studio Image Asset Studio → Notification Icons; reference via `default_notification_icon` meta-data | [tutorialpedia](https://www.tutorialpedia.org/blog/how-to-change-the-android-notification-icon-status-bar-icon-for-push-notification-in-flutter/) |
| 2 | Background handler never fires in release | Function not top-level OR missing `@pragma('vm:entry-point')` (tree-shaken in release) | Make top-level (or static), add pragma, run on a real device (not debug-attached) | [Firebase docs](https://firebase.google.com/docs/cloud-messaging/flutter/receive) |
| 3 | iOS dev build never receives pushes | APNs auth key not uploaded OR using legacy `.p12` certificate that expired | Upload `.p8` in Firebase Console; certs expire annually, keys do not | [Firebase iOS](https://firebase.google.com/docs/cloud-messaging/ios/get-started) |
| 4 | Foreground notification never shows banner | FCM does NOT auto-display in foreground; you must mirror via `flutter_local_notifications` | Listen on `onMessage`, call `_local.show(...)` | [FlutterFire usage](https://firebase.flutter.dev/docs/messaging/usage/) |
| 5 | Channel importance change ignored after first run | Android caches channel settings on first creation; `createNotificationChannel` is no-op for existing IDs | Bump channel ID (`default_v2`) or delete + recreate the channel | [FLN docs](https://pub.dev/packages/flutter_local_notifications) |
| 6 | Cold-start tap lands on `/` then jumps to deep link | `go_router` `initialLocation` runs before FCM `getInitialMessage` resolves | Park payload in a Provider; router redirect reads provider AFTER auth gate hydrates | [Flutter#142988](https://github.com/flutter/flutter/issues/142988) |
| 7 | `getInitialMessage()` returns null on cold start (intermittent) | Race: called before plugin fully attached on iOS | Await `Firebase.initializeApp` first; call inside `WidgetsBinding.instance.addPostFrameCallback` | [Firebase docs](https://firebase.google.com/docs/cloud-messaging/flutter/receive-messages) |
| 8 | Android 13+ device shows no notifications | Missing runtime `POST_NOTIFICATIONS` permission | `FirebaseMessaging.requestPermission()` triggers Android prompt; OR call `flutter_local_notifications` `requestNotificationsPermission()` | [Android dev](https://developer.android.com/develop/ui/views/notifications/notification-permission) |
| 9 | Notifications dropped on Xiaomi/Huawei after the app sits idle | OEM aggressive battery management kills background process | Send as `priority: high` data+notification; in-app dialog directing to "Auto-start" / "Protected apps" settings; consider `disable_battery_optimization` | [Pushy](https://support.pushy.me/hc/en-us/articles/360043864791) |
| 10 | iOS rich notification never displays the image | Missing Notification Service Extension OR HTTP (not HTTPS) URL OR image > 300 KB | Add NSE target with `FIRMessaging.extensionHelper`; serve HTTPS; resize <300KB; test on real device | [Firebase rich](https://firebase.google.com/docs/cloud-messaging/flutter/receive-messages) |
| 11 | Token differs between debug and release | Debug uses sandbox APNs environment, release uses production; Firebase maps tokens per environment | Upload BOTH dev + prod APNs keys (or one universal key); never hardcode tokens | [FlutterFire APNs](https://firebase.flutter.dev/docs/messaging/apple-integration/) |
| 12 | `onTokenRefresh` fires repeatedly, backend fills with dead tokens | Treating tokens as user-scoped instead of device-scoped; missing failure-driven cleanup | Store `(userId, deviceId, token, updatedAt)`; delete on FCM `UNREGISTERED` send error; expire after 30 days idle | [Firebase token mgmt](https://firebase.google.com/docs/cloud-messaging/manage-tokens) |
| 13 | Provisional permission users never see banners | Provisional = "Deliver Quietly" (Notification Center only, no banner/sound) until user opts in | Document expected UX; surface an in-app upsell to upgrade to full permission | [Apple iOS 12 provisional](https://github.com/iosbrain/iOS-12-Provisional-Authorization-for-Quiet-Notifications) |
| 14 | iOS silent (`content-available`) push not waking app | Throttled by iOS to ~2-3/hour; also blocked in Low Power Mode | Use sparingly; combine with visible push for critical sync; do not rely on for real-time | [Pushy gist](https://gist.github.com/gdeglin/98aeda28035b45cef04bb6c2cb41a4aa) |
| 15 | Notification tap targeting a non-Home tab opens Home (bottom-nav `StatefulShellRoute`) | `GoRouter.go(tabRoute)` from the tap handler does NOT switch the `IndexedStack` branch | Use the `gorouter-statefulshell-deeplink` skill: park the resolved branch index, switch via process-global shell holder + `goBranch(idx, initialLocation: idx==currentIndex)` | nav-bar tap switches tabs but notification tap doesn't |
| 16 | A crafted push route navigates somewhere the URL allowlist should have blocked | `setPath(rawRoute)` from the payload runs BEFORE the deep-link allowlist/sanitizer | Resolve + allowlist-check the route FIRST, THEN `setPath` — never let the raw payload route bypass the same validation a Universal Link gets (OWASP MASVS) | a push payload reaches a gated/internal route |
| 17 | Hibrit local + FCM: aynı slot için iki bildirim gösteriliyor | Local 9:00:00 scheduled, FCM 9:00:01 fired; `cancelLocalCounterpart` çoktan fire olanı iptal edemez | OS-level dedup: `apns-collapse-id` (iOS) + Android `notification.tag` aynı deterministic string ile. Aynı key'li push'lar OS tarafında collapse/replace. Tam çözüm değil (local + FCM aynı anda gelirse iki sistem mekanizması farklı görünür), ama FCM çiftlerini öldürür | [APNs collapse-id](https://developer.apple.com/documentation/usernotifications/sending-notification-requests-to-apns) |
| 18 | iOS foreground'da bildirim gelir ama banner görünmez (sessiz) | `UNUserNotificationCenter` delegate set edilmemiş → iOS default davranış foreground'da yutmak | `AppDelegate.application(...)` içinde `UNUserNotificationCenter.current().delegate = self`; `willPresent` override → iOS 14+ `[.banner, .sound, .badge, .list]` döndür | [Apple UNUserNotificationCenterDelegate](https://developer.apple.com/documentation/usernotifications/unusernotificationcenterdelegate) |
| 19 | `_firebaseBackgroundMessageHandler` içinden `flutter_local_notifications.initialize()` çağrılınca app deadlock | Background isolate'tan plugin init MethodChannel deadlock'a girer | Background handler'da SADECE light işler: `cancelLocalCounterpart`, key-value yaz, breadcrumb. `flutter_local_notifications` init main isolate'ta kalsın | [flutter_local_notifications#1730](https://github.com/MaikuB/flutter_local_notifications/issues/1730) |
| 20 | `zonedSchedule` yanlış zamanda fire ediyor (UTC olarak schedule etmiş) | `tz.local` default UTC; `flutter_timezone` ile init edilmeden zonedSchedule tz yanlış kabul ediyor | `main()`'de: `tz_data.initializeTimeZones(); tz.setLocalLocation(tz.getLocation(await FlutterTimezone.getLocalTimezone()))` — bunlar SCHEDULE'dan ÖNCE | [flutter_timezone](https://pub.dev/packages/flutter_timezone) |
| 21 | `zonedSchedule` çağırıldı, hata yok, ama bildirim gelmiyor — debug zor | flutter_local_notifications geçmiş `targetDt` için sessizce hiçbir şey yapmaz; "scheduled" iddiası logsuz | Schedule etmeden önce `if (targetDt.isBefore(DateTime.now())) { debugPrint('skip past'); return; }` guard ekle | empirical |
| 22 | Local + FCM ortamında para formatı bildirimlerde tutarsız (₺79,99 vs TRY 79.99) | Mobil Dart `intl` `'tr'` kısa kod sessiz fallback; server Deno `Intl.NumberFormat('tr-TR', ...)` doğru resolve eder | Bkz [`intl-currency-locale-resolve`](../intl-currency-locale-resolve/SKILL.md) — `resolveLocale('tr')` → `'tr_TR'` kullan | production Bug 11 |
