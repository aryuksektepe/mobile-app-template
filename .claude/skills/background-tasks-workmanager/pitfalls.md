# Background Tasks — Pitfalls Catalog

| # | Symptom | Cause | Fix | Source |
|---|---|---|---|---|
| 1 | iOS task never fires on real device | `BGTaskSchedulerPermittedIdentifiers` missing OR identifier doesn't match registration | Add identifier to Info.plist; verify exact string match; enable Background Modes capability | [Apple BGTaskScheduler](https://developer.apple.com/documentation/backgroundtasks) |
| 2 | Android task runs in dev, never on Xiaomi/Huawei real device | OEM aggressive battery saver kills background work | In-app dialog: "Pil koruması" → deep link to OEM settings (Xiaomi: Auto-start; Huawei: Protected apps). Same workaround as `notifications-fcm` pitfall #9 | [Pushy OEM workaround](https://support.pushy.me/hc/en-us/articles/360043864791) |
| 3 | Callback never fires in release build | Top-level function missing `@pragma('vm:entry-point')` — tree-shaken | Add the pragma + ensure function is TOP-LEVEL (not class member) | [Flutter pragma docs](https://api.flutter.dev/flutter/dart-vm/dart-vm-library.html) |
| 4 | Task registered with `NetworkType.unmetered` runs never on user with cellular-only | Constraint never satisfied | Use `NetworkType.connected` for general sync; `unmetered` only for large bulk syncs the user can defer | [WorkManager constraints](https://developer.android.com/topic/libraries/architecture/workmanager/how-to/define-work) |
| 5 | iOS task killed mid-execution | Overran 30s budget for BGAppRefreshTask (or longer for BGProcessingTask) | Keep work small; chunk large work across multiple invocations; use BGProcessingTask for >30s work | [Apple BGTask budgets](https://developer.apple.com/documentation/backgroundtasks/bgapprefreshtask) |
| 6 | Android: periodic task registered for 5 min, never runs | Android WorkManager minimum period is 15 min | Don't set < 15 min frequency. The library silently accepts smaller values but executes at 15+ | WorkManager docs |
| 7 | Task hits 401 on backend, retries forever | Refresh-token interceptor needs auth context but isolate has no auth state | Read tokens from `flutter_secure_storage` at top of callback; if refresh needed, do it inline; on failure → return false (workmanager backoff) | [Background isolate docs](https://docs.flutter.dev/development/packages-and-plugins/background-processes) |
| 8 | iOS Low Power Mode → tasks never fire | Apple disables BGTasks in Low Power | Don't depend on BGTasks for anything user-visible; use push notifications for critical sync triggers | [Apple Low Power Mode](https://support.apple.com/en-us/HT205234) |
| 9 | Android 12+ won't schedule WorkManager on cold start | Apps targeting Android 12+ have restrictions on background-launched WorkManager registration | Register tasks after first foreground frame, not in cold-start of background isolate | [Android 12 changes](https://developer.android.com/about/versions/12/foreground-services) |
| 10 | Crash in callbackDispatcher leaves task in "running" forever | No try/catch; uncaught exception in isolate | Wrap in try/catch + return false on error (per snippet) | this skill |
