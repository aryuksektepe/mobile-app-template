# Certificate Pinning — Pitfalls Catalog

| # | Symptom | Cause | Fix | Source |
|---|---|---|---|---|
| 1 | Entire user base bricked overnight | Single pin shipped + cert rotated server-side | ALWAYS ship primary + backup pin; rotate backup → primary before cert expiry | [OWASP MASVS-NETWORK](https://mas.owasp.org/MASVS/05-MASVS-NETWORK/) |
| 2 | Pin works first launch, fails after cert renewal (same key) | Pinned the cert DER, not the SPKI public key | Switch to SPKI hash — survives cert reissuance if keypair preserved | [OWASP pinning cheatsheet](https://cheatsheetseries.owasp.org/cheatsheets/Pinning_Cheat_Sheet.html) |
| 3 | App allows MITM in release | `badCertificateCallback` always returns `true` ("we'll fix it later") | Hard-rule: callback returning unconditional true in release = security incident. Use `kDebugMode` guard | [Flutter HttpClient docs](https://api.flutter.dev/flutter/dart-io/HttpClient/badCertificateCallback.html) |
| 4 | Charles/Proxyman doesn't work even in debug | Forgot to allow user-installed certs in Android `network_security_config.xml` debug-overrides | Add `<debug-overrides>` block with `src="user"` | [Android Network Security Config](https://developer.android.com/training/articles/security-config) |
| 5 | First production call fails with `HandshakeException` | Pin was extracted from STAGING endpoint, not PROD | Re-extract from prod hostname; verify with `openssl s_client -servername PROD_HOST` | OpenSSL docs |
| 6 | iOS works, Android fails with cleartext to API | `network_security_config.xml` has `cleartextTrafficPermitted="false"` but server is HTTP | Server must be HTTPS for pinning to apply; HTTP is rejected by config | [Android NSC](https://developer.android.com/training/articles/security-config) |
| 7 | Pinning silently OFF — production calls succeed but no SPKI check | Custom adapter not assigned to dio (`dio.httpClientAdapter = adapter` missing) | Verify assignment; smoke test with intentionally-bad pin in dev = expected fail | this skill's own pattern |
| 8 | App rejected by Apple App Review with "uses ATS exception" | Set `NSAllowsArbitraryLoads=true` in Info.plist for "ease" | Remove blanket exception; rely on per-domain pins + valid CAs | [Apple ATS guide](https://developer.apple.com/documentation/bundleresources/information_property_list/nsapptransportsecurity) |
| 9 | Pin works in app but breaks WebView API calls | WebView uses Android system WebView, not the pinned Dio client | WebView pinning requires `WebViewClient.shouldInterceptRequest` — complex; usually accept system trust for WebView, document risk | [Android WebViewClient](https://developer.android.com/reference/android/webkit/WebViewClient) |
| 10 | Rotation drill never tested, breaks at production cert expiry | Backup pin shipped but never verified to match the next cert | Drill: deploy a test endpoint with the "new" cert; flip primary↔backup; verify both work; rehearse before real rotation | OWASP MASVS-RESILIENCE |
