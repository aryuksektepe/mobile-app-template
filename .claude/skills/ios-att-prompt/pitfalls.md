# ATT — Pitfalls Catalog

10 entries from Apple HIG / App Review reports / FlutterFire / Adjust + Singular SDK docs.

| # | Symptom | Cause | Fix | Source |
|---|---|---|---|---|
| 1 | IDFA opt-in rate ~25% (industry good = 40-60%) | ATT prompt fired at first launch (no user value yet) | Defer to post-onboarding / after first FR-1 success; add pre-prompt | [Playwire ATT guide](https://www.playwire.com/blog/mastering-idfa-opt-in-rates-the-complete-apptrackingtransparency-guide-for-ios-apps) |
| 2 | App crashes the moment `requestTrackingAuthorization()` is called | `NSUserTrackingUsageDescription` missing from Info.plist | Add the key; without it iOS auto-denies + may abort | [Apple ATT docs](https://developer.apple.com/documentation/apptrackingtransparency) |
| 3 | Adjust/AppsFlyer first session ships with empty IDFA permanently | Tracking SDK initialized BEFORE ATT response — first session ships without IDFA, attribution lost for device | Gate SDK init behind `AttService.request()` completion; set `attConsentWaitingInterval` ≤ 360s | [Adjust ATT setup](https://dev.adjust.com/en/sdk/flutter/features/att/) |
| 4 | "User ID is `00000000-0000-0000-0000-000000000000`" in analytics | Calling `getAdvertisingIdentifier()` after ATT denial — Apple returns the zero-UUID | Check `AttService.granted` first; never log/use the zero-UUID as identifier | [Apple ASIdentifierManager](https://developer.apple.com/documentation/adsupport) |
| 5 | App Store reject — 5.1.2(i) "purpose string doesn't accurately describe data use" | `NSUserTrackingUsageDescription` is vague ("for a better experience") OR doesn't match the partners listed in App Privacy / Privacy Manifest | Rewrite to be specific (categories + purposes); cross-check App Privacy + `NSPrivacyTrackingDomains` | [Apple Reviewer Notes](https://developer.apple.com/app-store/review/guidelines/#privacy) |
| 6 | Pre-prompt rejected for "mimicking system UI" | Pre-prompt uses black bar / Apple-style icons / language identical to system | Use your app's design language; clearly app-branded; no system iconography | [Sourcepoint best practices](https://docs.sourcepoint.com/hc/en-us/articles/4401990990355-Best-practices-iOS-tracking-message) |
| 7 | App Store reject — "consent gated functionality" | A feature was hidden / disabled when ATT was denied | Feature parity required: ATT cannot gate functionality. Only personalization/measurement may change | [Apple HIG](https://developer.apple.com/app-store/user-privacy-and-data-use/) |
| 8 | iOS 14.4 device sees no prompt + IDFA returns | ATT only enforced from iOS 14.5; pre-14.5 returns IDFA without prompt | Treat pre-14.5 as `authorized` (no-op) — this is correct behavior; not a bug | [Apple iOS 14.5 release notes](https://developer.apple.com/news/?id=hx9s63c5) |
| 9 | EU users see ATT but not GDPR banner → fine risk | Conflating ATT (iOS-only) with GDPR consent (legal) — they are SEPARATE | Show GDPR consent banner first (CMP / Consent Mode v2); ATT pre-prompt at natural moment after | [Google Consent Mode v2](https://developers.google.com/tag-platform/security/guides/consent) |
| 10 | Calling `requestTrackingAuthorization()` from `main()` returns `notDetermined` instantly | iOS won't show the prompt while the app is launching / not in foreground | Call only after first frame + app in foreground + user gesture (e.g. button tap) | [Apple ATT docs](https://developer.apple.com/documentation/apptrackingtransparency/attrackingmanager/3547037-requesttrackingauthorization) |
