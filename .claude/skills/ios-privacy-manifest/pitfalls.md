# Privacy Manifest — Pitfalls Catalog

10 entries from Apple developer docs, App Store Connect reject reports (Bitrise / Singular / community), and FlutterFire issue tracker.

| # | Symptom | Cause | Fix | Source |
|---|---|---|---|---|
| 1 | Upload rejected with `ITMS-91056: Invalid privacy manifest. Missing API declaration: UserDefaults` | App uses `shared_preferences` (every Flutter app) but `NSPrivacyAccessedAPICategoryUserDefaults` not declared | Add the entry with reason `CA92.1` | [Apple Required Reason APIs](https://developer.apple.com/documentation/bundleresources/describing-use-of-required-reason-api) |
| 2 | Upload rejected `ITMS-91065: Missing signature for SDK X` | A commonly-used SDK (Firebase, Sentry, RC, Adjust) is on an old version without the manifest+signature | Bump the SDK to its first manifest-shipping version (Firebase 10.20+, Sentry 8.18+, RC 4.31+) | [Bitrise blog](https://bitrise.io/blog/post/enforcement-of-apple-privacy-manifest-starting-from-may-1-2024) |
| 3 | App Review reject 5.1.x — App Privacy form contradicts manifest | App Store Connect → App Privacy form was filled before adding the manifest, and they diverged | Reconcile both in one pass; treat the manifest as source of truth, update the form | [Apple App Review](https://developer.apple.com/app-store/review/guidelines/#privacy) |
| 4 | ATT prompt never shows although `NSPrivacyTracking: true` | `NSUserTrackingUsageDescription` missing from Info.plist (separate requirement) | Add the usage description (skill: `ios-att-prompt`) | [Apple ATT](https://developer.apple.com/documentation/apptrackingtransparency) |
| 5 | Network calls to `app-measurement.com` silently fail on ATT-denied device | iOS blocks DNS to domains in `NSPrivacyTrackingDomains` when ATT is denied | This is correct behavior — confirm Firebase Analytics SDK handles the failure gracefully (it does); do NOT retry | [Apple Tracking Domains](https://developer.apple.com/documentation/bundleresources/privacy-manifest-files/describing-data-use-in-privacy-manifests) |
| 6 | New SDK added, no manifest update, upload succeeds anyway — but feature dead | iOS does NOT block at upload if a NEW Required Reason API gets called at runtime; only audit-time | Add the audit script to CI; manifest must be kept in sync with every dependency change | [Capgo guide](https://capgo.app/blog/privacy-manifest-for-ios-apps/) |
| 7 | Wrong reason code (e.g. `CA92.1` for a third-party SDK's UserDefaults) → App Review reject | `CA92.1` = own app data; `1C8F.1` = third-party SDK; codes are semantically tracked | Match the code to the caller: app code → `CA92.1`, SDK code → `1C8F.1` | [Apple reason codes](https://developer.apple.com/documentation/bundleresources/privacy-manifest-files/describing-use-of-required-reason-api) |
| 8 | Manifest file present in source but not in the built `.app` bundle | Forgot to add to Runner target membership in Xcode | Xcode → file → File Inspector → Target Membership ✓ Runner | [Apple bundle docs](https://developer.apple.com/documentation/bundleresources/adding-a-privacy-manifest-to-your-app-or-third-party-sdk) |
| 9 | Multiple manifests merged unpredictably | The same plist key appearing in app manifest AND a static framework's manifest is merged by Xcode; conflicts go undefined | Keep ONE manifest per binary (app vs each SDK); duplicate declarations are valid but use the most restrictive interpretation | [Apple WWDC23 session 10060](https://developer.apple.com/videos/play/wwdc2023/10060/) |
| 10 | `NSPrivacyCollectedDataTypeTracking: true` declared but `NSPrivacyTracking: false` | Conflicting declaration — if ANY collected data type is tracking, top-level `NSPrivacyTracking` MUST be true | Set top-level true; revisit ATT setup (skill: `ios-att-prompt`) | [Expo Privacy Manifest guide](https://docs.expo.dev/guides/apple-privacy/) |
